1. Determine which sequences to include in your build.

I previously did this in a 2-step approach by first building an HA tree and checking topology, then building other segment trees and performing a test Treesort run. Now, I have a build to do all of the steps at once and generating a `filtered` folder to slot into the Treesort replicate pipeline.

To use this build, copy the `base-build-filtering` directory and replace the `data` with updated sequences and metadata (ensure these have been properly set up for Treesort, i.e., with dates appended to strain names [see Note 1 at bottom]) and update the `config` as necessary (i.e., to add new dropped strains). Update the Snakefile to change filtering parameters, if needed.

Using the treesort-pipeline conda environment, cd into the directory and run this build with either `snakemake -s Snakefile --cores` or `nextstrain build --ambient .` If the build runs successfully, you should have a single Treesort-annotated tree. Confirm that this tree is parseable with your analysis pipeline (I keep finding new issues...) and, if so, you can move on to the actual pipeline!

2. Copy the `base-build-treesort` directory, then copy the generated `filtered` folder from the `base-build-filtering` (containing `filtered_*_filtered.txt`, `filtered_*.fasta`, and `metadata_dates.tsv`) there. Confirm that the `config.yaml` is set up for the correct number of HA and non-HA replicates.


3. Locally with the treesort-pipeline conda environment, run a dry-run with `snakemake -s Snakefile -n` to ensure that the build can run successfully.


4. Transfer the full directory to PARCC with `rsync`.


5. On PARCC using the treesort-pipeline conda environment, run the pipeline!
